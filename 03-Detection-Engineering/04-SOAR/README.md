# SOAR (Security Orchestration, Automation, and Response)

В данном разделе описана автоматизированная система реагирования, которая была построена для минимизации времени реакции на инциденты. Система связывает SIEM (Wazuh) с инструментом оркестрации (Shuffle) и позволяет автоматически блокировать атакующих.

## Архитектура системы
**Wazuh (Детект) ➔ Shuffle (Оркестрация) ➔ Python (Active Response) ➔ Email (Уведомление)**

1.  **Wazuh Manager:** Анализирует логи, генерирует алерты. Настроен на отправку событий уровня 10 и выше в Shuffle (через кастомный скрипт `custom-shuffle.sh`).
2.  **Shuffle:** Принимает вебхук, проверяет условия (Condition: уровень > 7) и запускает Python-узел.
3.  **Python-узел:** Авторизуется в Wazuh API (получает JWT-токен), формирует запрос на Active Response и отправляет его на Wazuh Manager.
4.  **Active Response:** Wazuh Manager отправляет команду агенту (Ubuntu). Агент выполняет скрипт `firewall-drop`, который добавляет правило в `iptables`, блокируя IP атакующего.
5.  **Email:** Отправляется уведомление на почту с деталями инцидента.

## Проблемы и их решения
В процессе настройки мы столкнулись с рядом сложностей:
*   **Шторм событий:** Wazuh отправлял в Shuffle всё подряд (включая `sudo`), что привело к лимитам и рекурсии. *Решение:* Подняли порог алертов до `<level>10</level>` в конфиге Wazuh.
*   **Ошибка 401 в API:** Shuffle не передавал заголовок `Authorization`. *Решение:* Заменили HTTP-узел на Python и реализовали полный цикл получения JWT-токена через `/security/user/authenticate`.
*   **Ошибка `Cannot read 'srcip'`:** Wazuh не видел IP в команде блокировки. *Решение:* В Python-скрипте вручную сформировали структуру `alert.data.srcip`, которую ожидает скрипт `firewall-drop`.
